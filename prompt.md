# Промпт для нейросети: создание ВКонтакте-бота на Python с каталогом услуг ортопедического салона

Ты — опытный Python-разработчик. Твоя задача — создать готовый к запуску проект ВКонтакте-бота на Python с каталогом услуг, прайс-листом, описанием услуг и кнопкой связи с менеджером.

Бот должен быть написан чисто, понятно, без лишних заглушек и без секретных данных в коде.

---

## 1. Общая задача

Создай проект ВКонтакте-бота для ортопедического салона.

Бот должен:

1. Показывать пользователю главное меню.
2. Показывать список услуг.
3. Показывать прайс-лист.
4. Показывать подробное описание каждой услуги.
5. Давать возможность связаться с менеджером.
6. Использовать тестовую базу знаний услуг и цен на примере ортопедического салона.
7. Хранить токен сообщества ВКонтакте в файле `.env`.
8. Использовать виртуальное окружение `.venv` для установки зависимостей.

---

## 2. Технологический стек

Используй:

- Python 3.11+;
- библиотеку `vk_api`;
- библиотеку `python-dotenv`;
- Bots Long Poll API;
- JSON-клавиатуры ВКонтакте;
- виртуальное окружение `.venv`;
- файл зависимостей `requirements.txt`.

Не используй сторонние базы данных, если они не нужны для минимальной работы. Данные об услугах можно хранить в Python-структурах, например в словаре или списке внутри модуля данных.

---

## 3. Функциональные требования

### 3.1. Главное меню

При старте диалога с ботом пользователь должен видеть приветственное сообщение и главное меню.

Кнопки главного меню:

- `Каталог услуг`;
- `Прайс-лист`;
- `Связаться с менеджером`;
- `О салоне`.

Также обработай команду или сообщение `старт`, `начать`, `/start`, если оно придет текстом.

---

### 3.2. Список услуг

При нажатии кнопки `Каталог услуг` бот должен показать список услуг ортопедического салона.

Формат вывода:

- заголовок, например: `Каталог услуг`;
- краткий список услуг;
- кнопки или элементы для выбора конкретной услуги.

Каждая услуга должна быть доступна для просмотра подробной информации.

---

### 3.3. Описание каждой услуги

При выборе конкретной услуги бот должен показать:

- название услуги;
- краткое описание;
- подробное описание;
- цену;
- длительность, если применимо;
- показания, если применимо;
- кнопку возврата в каталог;
- кнопку возврата в главное меню.

Пример формата:

```text
Услуга: Индивидуальные ортопедические стельки

Краткое описание:
Изготовление стелек по индивидуальным параметрам стопы.

Подробное описание:
Ортопедические стельки помогают правильно распределить нагрузку на стопы, суставы и позвоночник. Подходят при плоскостопии, болях в ногах, повышенной утомляемости и реабилитации после травм.

Цена: 6500 ₽
Длительность: 40 минут

Для записи свяжитесь с менеджером.
```

---

### 3.4. Прайс-лист

При нажатии кнопки `Прайс-лист` бот должен показать актуальный тестовый прайс-лист.

Формат:

```text
Прайс-лист ортопедического салона

Консультация ортопеда — 1500 ₽
Диагностика стопы — 1200 ₽
Индивидуальные стельки — 6500 ₽
...
```

Прайс-лист должен автоматически формироваться из базы знаний услуг.

---

### 3.5. Кнопка связи с менеджером

При нажатии кнопки `Связаться с менеджером` бот должен отправить сообщение с контактами менеджера.

Тестовые данные менеджера:

- имя: `Менеджер ортопедического салона`;
- телефон: `+7 900 000-00-00`;
- электронная почта: `manager@ortosalon.example`;
- ссылка на сообщения сообщества: `https://vk.me/ortosalon_example`;
- график работы: `Пн–Пт 09:00–18:00`.

Если возможно, добавь кнопку-ссылку на диалог с менеджером или сообществом. Если ссылка не задана, выведи текстовые контакты.

---

### 3.6. О салоне

Добавь раздел `О салоне`.

Тестовое описание:

```text
Ортопедический салон «Здоровые шаги» — тестовый пример.

Мы помогаем подобрать ортопедические изделия, средства реабилитации и аксессуары для здоровья опорно-двигательного аппарата.

В каталоге представлены консультации, диагностика, стельки, корсеты, бандажи, подушки и другие товары.
```

## 4. База знаний услуг

Заполни базу знаний тестовыми данными на примере ортопедического салона.

Требования к базе:

- минимум 8 услуг;
- у каждой услуги должен быть уникальный идентификатор;
- у каждой услуги должны быть: название, краткое описание, подробное описание, цена;
- при желании можно добавить длительность, показания и категорию;
- все цены указывай в рублях;
- данные должны быть реалистичными, но тестовыми.

Пример услуг, которые нужно включить или использовать как ориентир:

1. Консультация ортопеда;
2. Диагностика стопы;
3. Изготовление индивидуальных ортопедических стелек;
4. Подбор готовых ортопедических стелек;
5. Ортопедический корсет;
6. Бандаж на коленный сустав;
7. Ортопедическая подушка;
8. Массаж стоп;
9. Подбор компрессионного трикотажа;
10. Ортез на голеностопный сустав.

Пример структуры данных:

```python
SERVICES = [
    {
        "id": "consultation",
        "name": "Консультация ортопеда",
        "short_description": "Первичный прием специалиста.",
        "description": "Специалист осмотрит вас, соберет анамнез и даст рекомендации по подбору ортопедических изделий.",
        "price": 1500,
        "duration": "30 минут",
        "category": "Консультации"
    },
    ...
]
```

## 5. Требования к ВКонтакте-боту

Используй Bots Long Poll API сообщества.

Требования:

- бот должен работать от токена сообщества;
- токен должен читаться из файла `.env`;
- запрещается хранить токен в исходном коде;
- запрещается выводить токен в логи, сообщения или исключения;
- используй `python-dotenv` для загрузки переменных окружения;
- если `group_id` не указан, попробуй получить его автоматически через API;
- если автоматическое получение невозможно, поддерживай опциональную переменную `VK_GROUP_ID` в `.env`;
- бот должен корректно запускаться командой `python bot.py`;
- добавь понятные сообщения об ошибках, если токен не найден или недействителен.

## 6. Файл `.env`

Создай файл `.env.example` со следующим содержимым:

```env
VK_GROUP_TOKEN=your_group_token_here
# Необязательно: укажите, если автоматическое получение group_id не сработает
# VK_GROUP_ID=123456789
```

Реальный `.env` не включай в вывод. В `.gitignore` добавь:

```gitignore
.env
.venv/
__pycache__/
*.pyc
```

## 7. Виртуальное окружение и зависимости

Все зависимости должны устанавливаться в виртуальное окружение `.venv`.

В `README.md` укажи команды установки.

Для Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Для Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Для Windows CMD:

```cmd
python -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
```

Запуск бота:

```bash
python bot.py
```

## 11. Сценарий работы бота

Реализуй следующий пользовательский сценарий:

1. Пользователь открывает диалог с ботом или пишет `начать`.
2. Бот отправляет приветствие и показывает главное меню.
3. Пользователь нажимает `Каталог услуг`.
4. Бот показывает список услуг.
5. Пользователь выбирает услугу.
6. Бот показывает подробное описание услуги, цену и кнопки возврата.
7. Пользователь нажимает `Прайс-лист`.
8. Бот показывает список всех услуг с ценами.
9. Пользователь нажимает `Связаться с менеджером`.
10. Бот показывает контакты менеджера.
11. Пользователь нажимает `О салоне`.
12. Бот показывает краткую информацию о салоне.
13. На неизвестное сообщение бот вежливо отвечает и возвращает главное меню.

## 12. Требования к клавиатура

Клавиатура должна быть удобной и соответствовать логике меню.

Главное меню:

```text
Каталог услуг | Прайс-лист
Связаться с менеджером | О салоне
```

В каталоге услуг:

- каждая услуга должна быть отдельной кнопкой или элементом выбора;
- внизу должна быть кнопка `Главное меню`.

В карточке услуги:

- кнопка `Назад в каталог`;
- кнопка `Главное меню`;
- при необходимости кнопка `Связаться с менеджером`.

Используй `payload` или текстовые команды так, чтобы бот мог однозначно понять действие пользователя.

## 13. Обработка ошибок

Предусмотри обработку следующих ситуаций:

- отсутствует `.env`;
- отсутствует `VK_GROUP_TOKEN`;
- неверный токен;
- ошибка запроса к VK API;
- неизвестное действие пользователя;
- пустая база услуг;
- превышение лимита текста сообщения, если такое возможно.

Пользователю показывай дружелюбные сообщения, например:

```text
Произошла ошибка. Попробуйте еще раз чуть позже или свяжитесь с менеджером.
```

Технические ошибки записывай в лог.

Проект считается готовым, если:

- бот запускается локально;
- токен берется из `.env`;
- зависимости устанавливаются в `.venv`;
- главное меню работает;
- каталог услуг отображается;
- можно открыть описание услуги;
- прайс-лист формируется из тестовых данных;
- кнопка связи с менеджером показывает контакты;
- нет секретов в коде;
- код разбит на модули;
- есть `requirements.txt`, `.env.example`, `.gitignore`, `README.md`;
- используются тестовые данные ортопедического салона;
- неизвестные сообщения обрабатываются вежливо и без ошибок.
